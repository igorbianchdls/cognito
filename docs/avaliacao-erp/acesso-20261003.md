## Escopo aplicado

Os dois primeiros pontos da revisão foram implementados:

- `shared.is_tenant_member` e `shared.has_erp_capability` exigem empresa com status `active` e vínculo ativo. Empresas `suspended` e `disabled` deixam de autorizar leitura e escrita, inclusive para owner/admin.
- As 82 políticas SELECT do ERP exigem acesso ao módulo correspondente. Gerenciar o módulo também permite ler seus registros, para preservar alterações com retorno, validações financeiras e fechamento de períodos.
- Cadastros de referência continuam disponíveis para os módulos que os utilizam. Uma permissão de relatórios isolada não libera títulos financeiros ou saldos.
- Anexos respeitam o acesso às suas associações. Notas de saída exigem vendas; notas de entrada exigem compras. Itens, totais e eventos fiscais seguem a nota de origem. Configuração fiscal e gestão de arquivos permanecem acessíveis ao perfil autorizado de configurações.
- Resultados de automações respeitam seu tipo e os módulos cujos dados podem conter.
- Vendas e compras consultam somente os identificadores da empresa, CNPJ, inscrição estadual e código municipal pela função privada `erp.fiscal_issuer_for_operations`. Essa função não retorna referências de segredos nem metadados da configuração fiscal.

As 14 políticas ALL existentes foram verificadas: exigem gerenciar o módulo e não reabrem leitura para perfis sem permissão. As políticas de escrita foram preservadas; passam a bloquear empresas desativadas por utilizarem a função compartilhada de autorização.

## Execução e manutenção

Os scripts usam as credenciais locais ignoradas pelo Git e TLS com certificado verificado. Não registram URLs ou credenciais em falhas remotas.

```powershell
node scripts/erp/read-access-smoke.mjs
$env:ERP_TEST_READ_ACCESS='1'
node scripts/erp/service-integrity-smoke.mjs
node scripts/erp/service-integrity-regression.mjs
Remove-Item Env:ERP_TEST_READ_ACCESS
node scripts/chatgptplugin-database-smoke.mjs
node scripts/erp/apply-read-access.mjs --check
node scripts/erp/verify-read-access.mjs
node scripts/erp/audit-schema.mjs --output=catalog-after-read-access-20261003.json
```

`apply-read-access.mjs --check` reconhece a migração já aplicada e confere seu SQL e catálogo. A aplicação exige `--apply --project=mtadnxqoqxzbdksktwdr` e testes aprovados para o mesmo hash de SQL.

O ERP deve executar a versão atualizada dos dois repositórios fiscais junto da migração, para utilizar a projeção limitada dos dados do emitente.
